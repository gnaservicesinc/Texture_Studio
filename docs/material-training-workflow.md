# Native material training workflow

Open a dataset in Dataset Studio, select the material or complete dataset you want to use, and send it to Model Training. Choose height, normal or roughness and the native grid. The app checks that every input and target has the declared dimensions. It references matching originals and creates exact crops when needed; it does not resize or pad training maps.

Each source resolution contributes one paired training sample. For square sources, the tier relative to the selected training size determines its initial crop:

| Source tier | Initial training sample |
| --- | --- |
| 1× | Full original field |
| 2× | Center crop |
| 4× | One choice among top left, top right, bottom left, bottom right and center |
| Existing sources larger than 4× | Random crop position within the original |

Preparation keeps the diffuse and selected target aligned at each tier. For supported Poly Haven sources, missing 1×, 2× and 4× original pairs are fetched into the source folder. Larger diffuse tiers already present remain usable, and their missing selected target can be fetched without downloading a new larger diffuse tier. Selecting a folder includes its eligible resolution tiers even when the selected original is smaller than the training grid.

**Randomize Crops when** chooses **Never**, **At the start of a new training run** (the default), or **Every epoch**. New runs reselect balanced initial crop positions. Every epoch refreshes their selected orientation augmentations. **Randomly Flip Crop** and **Randomly Spin Centercut Crops** are optional and default off. Selecting Never grays out both controls and suppresses their effects while remembering their checked states; it reuses the deterministic seed-zero prepared crop cache.

Randomly Flip Crop chooses equally among a vertical flip, horizontal flip, both, or unchanged. At every-epoch timing, it transforms the current cached crop and overwrites that crop, so subsequent flips build on the current orientation. Randomly Spin Centercut Crops instead rotates the original source by a random integer angle from 1 through 179 degrees and takes its center crop; every spin returns to the original source. The optional flip runs afterward, and the final paired crop replaces its cached version. Inputs and targets receive matching spatial transformations. Center spins use nearest integer sampling to preserve scalar and color codes, with the normal vectors rotated to match. The run keeps these mutable pairs and their history in its output folder's `crop-cache`; original source files and the original prepared dataset cache remain unchanged. A near-native center field without enough surrounding pixels keeps its cached pixels for that refresh and can still flip; the history records the skipped spin instead of introducing padding. Normal 2× and 4× center fields have enough support for every requested angle.

Native training flags are `--randomize-crops never|run|epoch`, `--random-flip`, and `--random-spin-centercut`. Never suppresses both augmentation flags. Existing saved settings with no crop fields use new-run timing and leave orientation augmentation off. A saved `randomFlip: true` retains the opt-in flip with new-run timing. Crop timing and both choices travel with training handoffs and are remembered without starting a run.

Choose **Model family** in Model Training. **PBRnxt refinement** starts with the pinned base or a compatible safetensors checkpoint. Its material adapter updates the selected RRDB output branch; developer mode also offers the corresponding decoder. **Compact scalar prototype** trains a standalone model for height or roughness, with one output channel. **Compact normal prototype** trains a separate model with three normal components. Each of these RGB compact runs trains one target map, keeps RGB diffuse input, and trains every weight from scratch unless a compatible compact checkpoint is selected. These RGB models need no base download. Switching the map automatically selects the matching RGB compact family. Compact models default to a learning rate of 0.001 when switching from PBRnxt; the rate remains directly editable. Select 512×512 for the initial trial. The default width is 32, with 999,937 scalar parameters or 1,000,515 normal parameters. These are prototypes whose learned quality must be evaluated on held-out materials. The separate one-channel **DepthPro Height Refiner** experiment is described below.

Training executes the complete mapping and gradients in Apple MPSGraph, averages accumulated map gradients, clips their global norm when enabled and updates Float32 Adam or AdamW state. Stop & Save finishes the active map and applies the available accumulated gradients, validates when enabled and writes a checkpoint. The separate Abort button cancels setup, training or a pending save and keeps checkpoints already saved. Save Checkpoint Now queues validation when enabled and a snapshot while training continues. Warm starts restore learned weights and the recorded step; optimizer moments, warmup and scheduling start fresh for the new run. Compact checkpoints contain complete standalone `model.safetensors` weights in either developer mode. Warm starts require the same compact family, target and width; PBRnxt LoRA adapters cannot be used as compact weights. Checkpoint comparison labels a compact model's seeded pre-training baseline **Untrained initialization**.

Compact models use a small fully differentiated encoder/decoder graph with separate compiled prediction, loss and gradient executables. The staged execution and frozen-feature caching described below apply to PBRnxt refinement.

Use **Local Models → Locate Material Model…** to load a native safetensors checkpoint or its exported folder in the primary app. Imported comparison photos may have any safely representable source dimensions; preparation creates the selected 256/512/1024 grid once for all candidates. Source dimensions do not need to match the model's grid. Developer Core ML packages have a separate import action.

A few hundred distinct material examples may support a useful model within the represented material types, but generalization is an experiment. Additional crops expose local details without creating new independent materials. The app's automatic extra-crop validation is a diagnostic on known subjects; it cannot establish performance on new subjects. Reserve entire materials outside training for the quality trial, and compare predicted maps and rendered materials against their references. A lower training loss alone is insufficient evidence that a compact model is useful.

**Training settings** exposes learning rate, optimizer, gradient accumulation, weight decay, constant or cosine scheduling and warmup. Advanced settings expose the moment coefficients, epsilon, gradient norm limit, seed, LoRA rank and alpha in both normal and developer modes. AdamW defaults to zero decay, preserving the earlier Adam recipe's regularization. Cosine scheduling uses an explicit minimum-rate ratio, defaulting to 0.1. One complete map is processed per forward/backward pass; accumulation averages multiple maps at unchanged weights before one optimizer application. Increasing accumulation increases work per step. The planned optimizer updates remain training map count × Updates per map. The run log, run record, checkpoints and exports record the effective recipe. See the [model configuration audit](training-audit.md) for default values, upstream evidence and fixed precision/loss choices.

Set **Model name** before starting training. The automatic name appears as editable text and stays visible when focused. The name is remembered with training settings and stored in snapshots, exports and run records; Saved Models displays it. Clearing it uses the selected warm-start model's name or the dataset name and target map. Output folders still have unique generated names.

Training actions stay at the bottom of the page. Progress shows the preparation, model setup, training and saving phases, total completed/planned steps, the active step, epoch, material map or validation crop, and the current forward/backward/optimizer operation. It also shows the latest step duration, effective learning rate and accumulation position. Crop refreshes show the cached pairs processed and preserve the completed steps and current epoch, as do validation and checkpoint work. Quick-check intervals and crop counts accept nonnegative whole numbers without preset upper caps; setting either to 0 disables periodic quick checks. Disabled validation is a supported preference and does not display an empty-validation warning.

Quick-check and checkpoint frequency each have an **epoch / step** dropdown to the right of the interval. Both default to epoch, with periodic quick checks and checkpoints off until configured. An epoch is a complete shuffled pass through the training materials. A step is one successful optimizer update, counted from the start of this run. Epoch schedules fire after a complete pass, and checkpoint saving includes the full enabled validation pool. Each frequency is independent. Existing active schedules that lack a unit keep their previous counts and use step, preserving their former optimizer-update frequency; disabled legacy schedules adopt epoch. A zero interval disables that periodic action; requested saves and final export still run.

Earlier PBRnxt 512 runs spent about 9 ms preparing each pair versus 5–6 seconds on the model step. Keep the inexpensive integrity checks. The compact prototype is now available; fresh M2 Max probes average 0.225 seconds per warmed scalar step at 512 and 0.698 seconds at 1024. A 1K trial uses the same architecture and can continue the same target's compact weights when original maps supply that native grid. These timings do not qualify learned quality. See the [1K measurements and fixes](validation/compact-material-fixes-and-1k-trial-2026-10-11.md). The earlier [concurrency assessment](validation/training-concurrency-2026-10-10.md) applies to concurrent copies of PBRnxt; concurrent training remains an unmeasured option.

After final weights are published, cleanup, model-library refresh, source-dataset restoration or optional upload errors are reported as completion notices. They retain the completed training state and saved model. Cleanup accepts genuine Finder metadata in owned temporary caches while preserving unrelated files. Existing `hf auth login` credentials are discovered natively alongside environment and app Keychain tokens; an upload's verified commit is retained if a later local catalog refresh fails.

An unreadable, changed, malformed or numerically invalid sample is logged and skipped for the remainder of the run. Valid training materials continue, and checkpoints can still be saved when part or all of the validation pool fails. Rejected microbatches do not contribute gradients; the remaining gradients use their actual sample count. An overflowing optimizer group leaves weights and moments unchanged and quarantines that group's samples. The progress panel reports skipped samples; details are retained in the operation log, `skipped-samples.json` and `run.json`. A validation result shows how many crops succeeded and were skipped. If none succeed, validation is marked unavailable and saving continues without claiming a validation score. If no valid training samples remain, the run stops and saves its current weights, reporting explicitly when no training was performed. Explicit Abort and task cancellation retain their cancellation behavior; model contracts and system errors remain fatal.

Training maps are already planar. Their PNG alpha channels and supported transparency keys do not change crop selection or numeric color/map values. In Texture Studio, projected full-frame geometry determines the crop independently of source opacity. Diffuse processing preserves that opacity, including interior holes, while visible color and lighting are processed with correct premultiplied-alpha handling.

Validation computes the forward model and losses without constructing gradients or optimizer state. The forward pass runs in stages on the complete native grid. Frozen encoder and decoder blocks execute as single stages when their conservative working set permits it. Blocks containing adapters, and downstream blocks whose inputs depend on adapters, retain finer boundaries for bounded differentiation and replay. Intermediate GPU tensors are released after their last consumer. Reverse-stage differentiation carries gradients through every selected layer; RAM checkpoints are bounded, and discarded activations are recomputed using unchanged weights. A bounded cache reuses only adapter-independent features for unchanged diffuse pixels and encoding. Neither cache writes activation files to disk. Compact attention-mask labels are supplied as feeds to prevent the graph compiler expanding masks for unused stages. Capacity checks include the working set of one reverse stage and the native forward tensors before compilation. Decoder upsampling repeats the original samples through differentiable concatenation.

Activation checkpoints retain compact GPU buffers directly, avoiding CPU readbacks and repeated uploads during replay. Their default budget is the smallest of 12 GiB, one quarter of the machine's safe training capacity and half the capacity remaining after the estimated working set. The separate frozen-feature cache remains capped at 2 GiB. Staged execution reuses symbolic model and derivative metadata, compiled program packages and immutable weight uploads; compiler and executable workspaces are still released. Progress events are delivered to the UI in batches while the complete event log is saved. Full-size training throughput depends on the selected grid, adapter scope and required replay.

Source integer maps remain unchanged. Float32 model tensors explicitly divide their decoded codes by the code maximum according to the recorded input/target contract. This model-input conversion is separate from the original arrays and exact crop exports. Normal green-channel conversion is explicit for a declared DirectX source.

Review reference, base and checkpoint maps at full pixels, on a displaced surface and on new photographs. A test photograph is prepared by the same diffuse-processing path used in Texture Studio. Training loss alone does not establish useful detail, generalization or absolute depth. Promotion into Texture Studio remains an explicit selection.

Export includes the separate LoRA. Developer export also includes the complete fused model. Combining adapters requires the same exact base, target, scope and trained layers; weights can be adjusted without changing the original checkpoints. Package checksums cover every weight, configuration and notice file.

Settings hold the working folder, local weights, Preparation workers and optional Hugging Face token. Preparation workers defaults to available CPU cores; preparation reduces actual concurrency when fewer source sets or the memory budget require it. Initial source inspection uses a bounded concurrent pool and reuses unchanged source summaries. Temporary training data contains only the diffuse variants and selected output target; changing the target prepares the required pair before training. No runtime installation or environment setup is required. Model files are downloaded only when requested, and a full checkpoint permits safe removal of the verified downloaded base weights.

## DepthPro Height Refiner experiment

Choose **DepthPro Height Refiner** for the separate one-channel depth-to-height experiment. It generates DepthPro camera depth from the prepared diffuse field once, restores the meter prediction to the exact paired grid, and caches Float32 raw meters plus full-field normalized reciprocal depth. The refiner sees only that normalized depth channel and predicts the original height target's integer codes divided by their code maximum. Training epochs reuse the cached prediction; RGB compact models retain their RGB input contract. A matching local DepthPro Core ML model is required, and checkpoints record its exact SHA-256 and preparation contract. See the [refiner contract, evaluation and licensing status](depthpro-height-refiner.md).

Checkpoint Compare permits a single checked checkpoint with **Include untrained compact initialization** unchecked, whether a source height reference is available or the output is inspected alone. An initialization can run without checked checkpoints. Among model-selection choices, only selecting no checkpoints and excluding the initialization leaves nothing to run. Source selection and checkpoint compatibility checks still apply.
