# Native material training workflow

Open a dataset in Dataset Studio, select the material or complete dataset you want to use, and send it to Model Training. Choose height, normal or roughness and the native grid. The app checks that every input and target has the declared dimensions. It references matching originals and creates exact crops when needed; it does not resize or pad training maps. Subjects and crop ancestry govern train/validation separation.

Start with the pinned base, or select a compatible safetensors checkpoint as the warm start. A material adapter updates the selected output branch; developer mode also offers the corresponding decoder. Training executes the complete mapping and gradients in Apple MPSGraph, clips gradient norm and updates Float32 Adam state. Stop & Save completes the current update, validates when enabled and writes a checkpoint. The separate Abort button cancels setup, training or a pending save and keeps checkpoints already saved. Save Checkpoint Now queues validation when enabled and a snapshot while training continues. Warm starts restore learned weights and the recorded step; optimizer moments are initialized for the new run.

Set **Model name** before starting training. The name is remembered with training settings and stored in snapshots, exports and run records; Saved Models displays it. Leaving it blank uses the selected warm-start model's name or the dataset name and target map. Output folders still have unique generated names.

Training actions stay at the bottom of the page. Progress shows the preparation, model setup, training and saving phases, total completed/planned steps, the active step, epoch, material map or validation crop, and the current forward/backward/optimizer operation. Validation and checkpoint work preserve the total training position. Quick-check intervals and crop counts accept nonnegative whole numbers without preset upper caps; setting either to 0 disables periodic quick checks. Disabled validation is a supported preference and does not display an empty-validation warning.

Validation computes the forward model and losses without constructing gradients or optimizer state. The forward pass runs in stages on the complete native grid, with boundaries at encoder/decoder blocks and dense residual blocks. Intermediate GPU tensors are released after their last consumer. Reverse-stage differentiation carries gradients through every selected layer; RAM checkpoints are bounded, and discarded activations are recomputed using unchanged weights. A bounded cache reuses only adapter-independent features for unchanged diffuse pixels and encoding. Neither cache writes activation files to disk. Compact attention-mask labels are supplied as feeds to prevent the graph compiler expanding masks for unused stages. Capacity checks include the working set of one reverse stage and the native forward tensors before compilation. Decoder upsampling repeats the original samples through differentiable concatenation.

Activation checkpoints retain compact GPU buffers directly within the same byte budget, avoiding CPU readbacks and repeated uploads during replay. Staged execution reuses symbolic model and derivative metadata and immutable weight uploads; compiler and executable workspaces are still released. Progress events are delivered to the UI in batches while the complete event log is saved. These changes reduce setup, copying and UI work; full-size training throughput still depends on the selected grid, adapter scope and required replay.

Source integer maps remain unchanged. Float32 model tensors explicitly divide their decoded codes by the code maximum according to the recorded input/target contract. This model-input conversion is separate from the original arrays and exact crop exports. Normal green-channel conversion is explicit for a declared DirectX source.

Review reference, base and checkpoint maps at full pixels, on a displaced surface and on new photographs. A test photograph is prepared by the same diffuse-processing path used in Texture Studio. Training loss alone does not establish useful detail, generalization or absolute depth. Promotion into Texture Studio remains an explicit selection.

Export includes the separate LoRA. Developer export also includes the complete fused model. Combining adapters requires the same exact base, target, scope and trained layers; weights can be adjusted without changing the original checkpoints. Package checksums cover every weight, configuration and notice file.

Settings hold the working folder, local weights, Preparation workers and optional Hugging Face token. Preparation workers defaults to available CPU cores; preparation reduces actual concurrency when fewer source sets or the memory budget require it. Initial source inspection uses a bounded concurrent pool and reuses unchanged source summaries. Temporary training data contains only the diffuse variants and selected output target; changing the target prepares the required pair before training. No runtime installation or environment setup is required. Model files are downloaded only when requested, and a full checkpoint permits safe removal of the verified downloaded base weights.
