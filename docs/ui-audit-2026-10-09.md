# Texture Studio UI audit — 2026-10-09

The audit covered the native Texture Studio, Model Training, Dataset, Trainer, Checkpoint Compare, Material Review, checkpoint library, local adviser and their shipped Python action paths.

| Verified issue | Result |
| --- | --- |
| Quick-check intervals, checkpoint intervals, update counts, LoRA rank and validation counts require stepper buttons. | Replaced with direct text entry, explicit units and inline validation. All steppers removed. |
| Photographic, surface and review sliders have no precise text editor. | Added typing/paste editors, including scientific notation, physical scale, display contrast/midpoint and zoom. Sliders remain optional. |
| Decimal display rounds values; a focused text draft can overwrite a slider or Reset change. | Float/Double editors retain round-trip precision and synchronize external changes while focused. |
| Predictive memory budgets hide training sizes, refuse rendering/export and disable adviser requests. | Removed badge, capability filtering, estimate vetoes, export confirmation and application-set Metal allocation caps from the shipped paths. |
| Finite zero training loss or validation error aborts a run and prevents saving. | Zero is accepted. Nonfinite numerical failures remain explicit errors. |
| Library refinement omits checkpoint scope and does not open Trainer. | Uses the checkpoint's recorded target/scope and opens the trainer. An explicit checked document handoff updates an already-open standalone Trainer. |
| Training selection can change during asynchronous setup. | Data controls respect the active operation; preparation and training use captured settings/material identities. Incoming handoffs wait until active work completes. |
| Trainer omits dataset, material and starting-model identities. | Added selected names, dataset path, starting checkpoint and refinement-scope feedback. |
| Overview hides idle failures and some pages hide stop/save controls. | Overview presents errors and operation results; overview, saved models and review retain operation controls. Trainer separates the stop/save row from its heading. |
| Comparison readiness checks the primary input instead of the chosen diffuse variant; generic instructions do not identify missing requirements. | Uses the same selected diffuse map as inference and displays the specific missing-input/model requirement. |
| Opening maps after a review retains an old manifest, decisions and Blender scene. | Both file-opening routes start a clean map-review session. |
| Saving decisions does not restore the saved review on next launch. | Successful saves update the restored review and selection; failed saves retain the previous review location. |
| Output-size menu lacks conventional 4096 while old recipes use 4098. | Added 4096; existing 4098 recipes retain their exact selected size. |
| The standalone training CLI cannot import its bundled bridge in isolated mode. | Added its local source bootstrap and a staged-bundle regression. All four isolated CLI entrypoints pass. |
| Build-and-run verification reports failure after a successful launch when its process-list pipe closes early. | Process matching now consumes the complete list; optimized build-and-launch verification passes. |

Developer mode retains automatic Hugging Face upload after training when authenticated, as requested. The trainer displays repository and visibility; saved choices remain authoritative. New visibility choices default to private. This change does not delete training sources or unique model files.

Numeric map processing and source pixels retain their existing precision contracts. Display editing does not rewrite exported numerical maps.

Validation: the complete Python suite passed **948 tests plus 224 subtests**. The native suite passed **187 tests executed, one optional RAW-photo test skipped**; **18** focused numeric/refinement/handoff tests passed after the final routing change. The additional isolated training-CLI fix passed with **65** targeted backend tests. The optimized Release build and launch passed. All five app bundles' backend sources match the checkout and their nested signatures verify. Installed `/Applications/Texture Studio.app` and its four bundled tools match the validated build; the installed app smoke passed. Build, test and installation logs are in `out/ui-overhaul-*.log`.

Native desktop automation was unavailable because its startup pipe failed. This audit used source/action-path inspection, compiled native tests and application smoke checks; a live click-through/visual inspection was not completed.
