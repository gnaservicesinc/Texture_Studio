# Loom Room source folders

Loom Room is the developer workspace for teaching the diffuse classifier and training material models. Start with a folder of original images, such as `/opt/ipde/sources_mats`. Opening it requires no dataset JSON or model setup.

1. Choose **Open Source Folder…** in Loom Room. The folder and its images appear in **Manage Images & Tags**. Browsing reads filenames and image headers; it does not load a model or hash every image.
2. Use **Add Images or Folders…**, or drop files into the dataset browser. The app copies their exact file bytes into the open source folder. Selected loose maps stay grouped by their original parent folder and recognized material family and resolution tier. Materials from different original folders remain separate, even when their names match.
3. In **Manage Images & Tags**, select an image and choose **Edit Tags…**. Set its map role and material type, or enter a custom type. Base Color and Diffuse are color inputs; Height, Roughness and Normal are separate surface targets. AO and other supplementary maps use **Additional Map**, so they cannot become diffuse inputs. **Assign Maps…** lets you pair files explicitly when their names are unclear.
4. The same sheet can rename the image's material folder. This renames the actual folder inside the source root; the root stays in place. **Actions → Move Folder Out…** moves a material and its originals together to another location and removes them from this folder's membership. You can manage these files inside the app; the list also follows changes made outside it.
5. Review **Originals** separately from **Training Crops**. New source folders default to a 2048 × 2048 training grid. A 1024 × 1024 original remains visible, but cannot supply a 2048 crop. Training Crops shows only the selected exact grid. Slightly different paired dimensions can share a crop from their common pixels. Preparation never scales the originals, and aligned crops preserve the original 16-bit height codes.
6. Label diffuse examples, then choose **Prepare Classifier Examples**. **Classifier Settings…** selects the output folder and uses the open source folder by default. The selected grid limits eligible examples; smaller originals remain available for inspection. Open the generated training-data folder in Create ML, train the classifier, export its Core ML model, then use **Choose Trained Classifier…** in Loom Room.
7. Refresh the material categories with that classifier. Select a category and train its Height / Displacement, Roughness and Normal models from the available paired maps. **Set Up Training** opens the Trainer; **Continue Saved Model** resumes an existing model. Classifier-only photos stay classifier examples; surface training requires paired maps for the selected target.
8. Use **Compare with References**, inspect the saved results, then choose **Approve for Generation** for models you accept. Training completion and approval are separate steps. Changed source membership requires an updated model before approval.

Image tags are optional macOS extended attributes. Teaching choices and generated training data live in app-managed storage; no JSON file is required in the original source root. Cached verification belongs to the current file identity. Changing or replacing its bytes invalidates that verification, and a copied file needs its own verification. Copies made through the app transfer existing user labels and map roles without inheriting the original file's verification. Full source checks happen when preparation needs them, and source image bytes remain intact.

Learned photo preparation and final material restoration are planned stages, with no trained models supplied by this workflow. The separate non-developer LoRA workflow is deferred.
