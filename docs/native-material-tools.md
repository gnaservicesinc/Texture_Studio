# Native material tools

Texture Studio includes a **Model Training** button in its toolbar and sidebar. It opens one guided workspace for preparing data, training/refining, comparing results and exporting a model. The four tools are also independently launchable inside `Texture Studio.app/Contents/Applications/`, sharing the same Swift UI components and bundled local Python backend:

| App | Main workflow |
| --- | --- |
| Material Review | Inspect original PNG/EXR maps, synchronized navigation, full-quality pop-out windows, and export originals for GIMP. Open the packed Blender review scene to inspect actual displaced geometry. Save human review decisions separately. |
| Checkpoint Compare | Select two or more compatible checkpoints, run the same photo through each on Metal, and inspect the resulting native maps together. Each run records the actual checkpoint hash. |
| Material Dataset | Select a material crop, inspect diffuse/height/roughness/normal originals, approve/exclude/reapprove, edit review notes, and save review notes. Automatic check crops stay out of normal browsing. |
| Material Trainer | Choose a dataset, native 1024/2048 size, height/roughness/OpenGL-normal target, base/checkpoint starting point, all materials or an explicitly named quick-fit material, updates per crop and resource limits. Run, resume, stop and save; inspect live logs and run folders. Manage, package and optionally upload checkpoints. |

Build and open any tool from the repository:

```sh
./script/build_and_run.sh run --tool review
./script/build_and_run.sh run --tool compare
./script/build_and_run.sh run --tool dataset
./script/build_and_run.sh run --tool train
```

Normal builds and Run actions use **Release**, under `build/TextureStudio/Build/Products/Release/Texture Studio.app`. The embedded tools are proper `.app` bundles with separate names and bundle identifiers, compiled through the existing Xcode project. The tool role is a bundle setting; `--tool ROLE` can also select a role for development. `--debug` explicitly chooses Debug and launches LLDB; working with your materials does not require a Debug build. `make package` includes all four tools, and `make install` installs the whole suite in `/Applications/Texture Studio.app` after checking that the installed app and its tools are closed.

Review can open a `review-manifest.json`, a saved review, or original image maps directly. `--review /absolute/path/review-manifest.json` selects a review at launch; `--dataset /absolute/path/dataset.json` selects a dataset. The current local 2K review opens on first launch when available. Maps retain their original dimensions; numeric-map display conversion affects only the screen image. Export Original copies the source file byte for byte, including its original PNG/EXR precision. GIMP receives a byte-identical editable copy, preserving dataset originals. Saved reviews reopen their per-candidate decisions and notes. Review decisions never select a production model automatically.

Use Runtime to locate Python, a working folder, and the pinned DINOv2 weights/source. A new installation creates its default working folder under Application Support when it first produces results. Existing runtime choices are shared across the tools and persist after installing a Release build. Python needs the project's dependencies plus the training dependencies (`Pillow`, `safetensors`, and the pinned encoder source); Hugging Face upload additionally needs `huggingface_hub`. Missing files are reported so they can be reconnected. Download Pinned Encoder installs an app-owned, checksum-verified copy; Remove Downloaded Encoder removes only that managed copy. Located external files remain in place.

DINOv2 uses PyTorch's native scaled dot-product attention on Metal. xFormers is optional and is not needed for this backend. Training records the selected attention backend and shows one informational runtime message. The three upstream “xFormers is not available/disabled” import notices are hidden only for CPU/Metal; other warnings and import failures remain visible. This does not change the pinned encoder source or weights.

Use Checkpoints → Locate to inspect the checkpoint schema, target, step and SHA256. Checkpoint filenames do not select architectures. Incompatible models fail explicitly. A comparison uses the same native source dimensions for each candidate, and a new output folder; it records a reopenable review manifest. The model's small contextual encoder grid does not replace the native material-head output grid.

Dataset edits change metadata only, with an expected index hash and recovery journal. The backend refuses stale selections and active training edits. Original PNG data, encoded values, precision and color tags are not rewritten. A small automatic diagnostic sample checks progress; fresh photographs and manual material review judge generalization and visible quality.

Changing native crop size automatically prepares matching crops from the recorded original maps, then selects that size-specific dataset. It does not scale a 1K crop to 2K. Preparation runs materials concurrently, using every available CPU core that fits the current memory headroom, with light lossless PNG compression (level 3). Exact existing crops are checksum-verified and copied without recompression; APFS uses independent copy-on-write clones when available. Progress reports include the worker count, estimated worker memory and completed materials. Nested OpenCV threads are bounded during parallel preparation to avoid oversubscribing the CPU. Original maps are decoded once per material/role for all missing crops. Source verification also uses an adaptive decoded-image cache; an explicit `--source-cache-mib` override remains available. Cancellation waits for workers before removing incomplete staging. Generated variants are cached; originals, notes and exclusions are retained. Keep the originals available when asking for new pixels; already prepared native crops are self-contained.

Starting training also prepares automatic checks if an older dataset still has a validation crop for every material. A seeded random 5% of sources (rounded up, at least one) provide one disjoint native check crop each. Sources with enough room for both training corners and a third check are preferred; a narrow source may use one training corner and the opposite check corner. All sources remain available for training. One-material quick fits name their material explicitly and get its own check crop, retaining every other material in the dataset. Check crops and split assignments are internal metadata, hidden from normal dataset browsing. This measures progress on familiar sources, not generalization or production quality; inspect fresh photographs manually later. Old datasets and saved runs are preserved.

Train with unreviewed crops includes approved crops and prepared crops that have not been inspected yet. Turning it off requires reviewing the selected training crops first. Excluded crops are always skipped. All materials trains the broader collection; One material for a quick fit tests fitting only the named surface without removing the other materials.

Resource limits use binary GiB consistently in the slider, text field and backend. The training ceiling is computed from installed unified memory, leaving the larger of 4 GiB or 10% for macOS, and respecting a configured MPS allocator watermark. The recommendation uses up to 80% of physical memory within Metal's reported working set. On a 64 GiB Mac with the usual Metal recommendation this gives approximately 51.2 GiB by default and a 57.6 GiB maximum; larger Macs scale automatically. Use recommended restores that machine-specific value. The backend enforces the chosen finite allocator limit and tracks cached CPU tensors plus Metal driver memory. Decoded training pairs enter a bounded, lazy LRU cache without changing maps, batching or update order; disposable pairs are evicted before stopping a memory-limited run. Allocating more memory helps when it avoids repeated work or admits a larger job; the ceiling does not preallocate unused RAM.

Texture processing uses the full available Metal working-set recommendation and machine headroom. Depth cleanup keeps available source detail through the requested 4K/8K output instead of silently limiting its working grid to 2K. Float32 EXR export selects larger render strips from current memory and encodes each strip in one contiguous buffer. Import/dimension limits, explicit model-grid contracts and display previews are separate from resource capacity.

Stop & Save sends SIGINT to the trainer, which retains completed optimizer updates. Resume uses `checkpoint.latest.pt` with optimizer state, rather than treating a weights-only checkpoint as resumable. Set the desired total updates per crop when extending a run. Choose **Start from base** for a new head using DINOv2 Base features, or **Refine checkpoint** to start a new run from learned weights. Refining an existing rank-8 DINOv2 LoRA checkpoint keeps its encoder adapters and contextual resolution fixed while training the material head; saved checkpoints and exports retain those adapters. Full dataset fitting, roughness and direct normal fitting are explicit training runs; opening the UI never starts one.

Export Package writes a compact inference checkpoint, model card, source/license information, checksum manifest and pinned encoder dependencies into a new directory. It does not embed the pretrained encoder, training source images or optimizer state. A frozen encoder plus learned material head is identified as that architecture, not as a DA3 LoRA. The upload panel shows the saved Hugging Face account, destination and visibility inline. Upload Selected Model creates a fresh package from the exact selected checkpoint SHA256, then uploads directly without another confirmation. A private per-checkpoint repository is suggested under the signed-in account; custom destination and visibility persist. Use `hf auth login` when no saved login is available, then Refresh Account. No token is displayed or stored by the Swift app. Upload starts only when clicked.

Use in Texture Studio records the selected height checkpoint hash and runtime dependencies, and automatically switches open Studio windows to that trained material-height source. The separate tools notify Studio too; Studio rechecks selection when activated. Changing a selection during processing applies after the current operation finishes. Local Models and the inspector show the active checkpoint and distinguish DINOv2 material height from the separate DA3 camera-depth model. Texture Studio loads the exact selected checkpoint on Metal, preserving learned height amplitude instead of applying camera-depth percentile normalization. Perspective/crop and explicit relief contrast still apply. This native material head currently supports 1024/2048 output; larger output is refused with an explanation. Roughness and direct-normal checkpoints can be trained and compared; Texture Studio currently integrates height checkpoints and derives OpenGL normals from that height.

Compare Checkpoints includes the untrained starting material head by default, so a single trained checkpoint can be compared against its starting output. DINOv2 is a feature encoder, not a pretrained height predictor: the new scalar head starts at 0.5, and the normal head starts flat OpenGL +Y. These outputs are labeled explicitly. The source photo, available reference map, sample ID, checkpoint step and SHA256 stay visible; every selected model opens in the review grid. Saved review manifests and GIMP/export filenames retain the sample and candidate identity.

Version 3 recipes retain the trained checkpoint path and SHA256, so reopening a recipe uses its recorded model even when another model is now selected globally. Runtime executables are resolved from local settings, never taken from a recipe. Explicitly choosing Use in Texture Studio replaces that photo's pinned model. Material exports record the actual trained checkpoint in depth-source.json. Changing the model clears the old rendered map and shows the source photo until Update Preview finishes.

Studio and each embedded tool have distinct application icons, generated with Core Graphics and Apple's iconutil from the small checked-in Swift source during the Xcode build. No generated icon binaries or model weights are added to Git.

Development commits go to `main`. Datasets, model weights, app bundles and generated review outputs stay outside Git. Enable Git LFS before publishing embedded model weights. Local experiment history and recovery records are preserved separately.
