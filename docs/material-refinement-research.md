# Material refinement research

**Historical research and DINOv2 experiment record.** DINOv2 material training and Studio activation are retired. The technical evidence below remains a historical record; retained checkpoint files can still be reviewed, but these plans do not describe an active production training backend. See [current model vetting and acceptance checks](material-model-vetting.md) and [native material tools](native-material-tools.md) for the current workflow.

Checked against primary project sources on 2026-10-07. This is an evaluation and training plan; the models below have not been integrated into Texture Studio or benchmarked on this Mac unless explicitly stated elsewhere in the validation report.

## What a material model should add

Keep the photographed weave, cracks, grain, and paint texture aligned with the original. Estimate illumination separately from reflectance; produce material relief and roughness without replacing the surface with a similar-looking generated texture. Judge improvements by the exported material under several Blender Cycles lights, alongside crops of the original photo.

The requested `depth-anything/DA3-GIANT-1.1` estimates **relative scene depth**, confidence, and camera geometry. It is a useful geometric prior, but its model card does not claim surface-specific PBR height or roughness training. Its 1.15B-parameter checkpoint is CC BY-NC 4.0; the upstream code's Apache-2.0 license does not change the checkpoint license. Texture Studio must identify the exact selected checkpoint and retain the raw prediction separately from artistic displacement. [Official DA3 GIANT 1.1 model card](https://huggingface.co/depth-anything/DA3-GIANT-1.1), [upstream model table and refreshed-checkpoint notes](https://github.com/ByteDance-Seed/Depth-Anything-3#-model-cards).

SuperMat is another image-space albedo/roughness/metallicity estimator with single-step inference, but it does not provide height or normals. Its official implementation prefers 512-pixel object images and depends on Stable Diffusion 2.1 weights. MatE more directly targets casual-photo rectification and PBR maps including height, using MatSynth/Poly Haven-derived training pairs. Its official repository says the Poly Haven evaluation set is released, but code and weights remain forthcoming. Its paper reports about five days of training on four NVIDIA A6000 GPUs. No released, licensed, Mac-tested MatE checkpoint was established here. These are watch-list items, not installed features. [SuperMat authors' description](https://hyj542682306.github.io/SuperMat/), [SuperMat implementation](https://github.com/hyj542682306/SuperMat), [MatE release status and evaluation set](https://github.com/TIPTOEHIGHERZ/MaterialExtraction), [MatE training details](https://arxiv.org/html/2512.18312v1#S7).

## Has Poly Haven material-height training already been done?

Yes, through **MatSynth**: its documented sources include Poly Haven, and its maps include normal, height, roughness, and reflectance. CHORD and StableMaterials document MatSynth training. This is not evidence of an existing DA3 GIANT material-height LoRA. CHORD's height is integrated from estimated normals; StableMaterials generates height jointly with other maps. These are different objectives from adapting a scene-depth model to preserve a particular surface photograph. [MatSynth dataset card](https://huggingface.co/datasets/gvecchio/MatSynth), [dataset paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Vecchio_MatSynth_A_Modern_PBR_Materials_Dataset_CVPR_2024_paper.pdf).

Poly Haven explicitly permits AI training with its CC0 assets. MatSynth also contains CC-BY materials, so filter by asset metadata if a CC0-only training set is wanted. Keep source URLs, license, physical-size metadata, checksums, and acquisition method. The hosted Poly Haven API has separate access terms requiring recognizable request identity and source credit in integrations; asset CC0 does not remove those API terms. [Poly Haven FAQ](https://docs.polyhaven.com/en/faq), [API terms](https://github.com/Poly-Haven/Public-API/blob/master/ToS.md).

## A practical next experiment on this 64 GB Mac

First benchmark Marigold IID on the rectified wicker and paint crops, with the exact model pinned, 512–768-pixel inference, batch one, a fixed seed, and Float32 raw output retained. Extract a low-frequency illumination correction and bounded roughness proposal; apply that correction to the higher-resolution source. Show side-by-side original/corrected color and adjustable contribution. Reject any result that erases weave or turns color variations into exaggerated relief. This is a proposed experiment, not a measured quality improvement.

Run one large model at a time. Release the Ollama adviser before DA3 or diffusion inference, then release the image model before Metal export. Final 1024/2048/4098/8192 output size is independent of ML input size: larger exported images do not create new inferred detail. Profile actual peak resident memory and Metal allocations at each inference size. Diffusers documents MPS support and sensitivity to memory pressure, including attention slicing and sequential inference; it does not guarantee every third-party CUDA pipeline will work on MPS. [Diffusers MPS guidance](https://huggingface.co/docs/diffusers/en/optimization/mps).

## Training plan for photo-preserving material relief

The curated source is **original photographic Poly Haven materials**, using original high-resolution maps rather than thumbnails or a dataset loader's default image decoding. Poly Haven documents photographic capture methods and excludes procedural/generative material creation. MatSynth is a research reference or acquisition index; only its Poly Haven subset with independently checked source fidelity fits this curation preference. See the [data precision and native crop contract](material-training-data.md) and the [actual White Stucco 02 header audit](data/white-stucco-02-header-audit-2026-10-07.json).

1. Build paired rendered-photo/material-map samples from hand-selected Poly Haven materials. Preserve the source maps; render varied lighting, camera angle, exposure, white balance, noise, and mild lens distortion from those maps as separate input augmentations. Albedo alone is insufficient input for learning shadow/specular removal. Augmented input renders do not replace the real source relief.
2. The initial learning pilot uses every curated source material for training, reserving a non-overlapping region of each for validation. Check whether the model learns the expected relief first; acquire fresh unique materials when evaluating generalization later. Real phone captures remain a later visual test. Duplicate assets and overlapping source pixels must not create misleading validation comparisons.
3. Keep original lossless 16-bit PNG height/OpenGL normal maps and their integer samples unchanged on disk. Audit bit depth, channel order, compression and dimensions, including EXR alternatives. Decode only active samples into Float32 tensors; do not gamma-correct numeric maps or min/max-normalize each crop. Preserve supplied normals as independent targets; any normals derived from height are separately identified. Declare relative-height offset/scale and physical footprint where independently known.
4. Start with a small supervised residual decoder or adapters over frozen image/depth features. Predict residual material height, roughness, and confidence, using a plane-removed DA3 prediction as one optional feature. LoRA is a parameter-efficient option, not a guarantee that the existing DA3 scene-depth head can learn the desired output unchanged.
5. Curate native 1024-pixel crops from original 4K/8K maps, and optionally native 2048-pixel crops. Cropping precedes any model-specific resize. Profile a batch-one forward/backward step at 512, 1024 and 2048 before selecting training size; a smaller memory probe does not replace the curated targets with downsampled ones. Prefer a lightweight/frozen-backbone pilot, accumulation and checkpointing where supported. Dataset storage stays 16-bit PNG; Float32 targets/loss calculations and optional mixed-precision model arithmetic are separate choices. No claim that 64 GB can train full GIANT at 1K/2K is established yet.
6. Evaluate height gradients, normal consistency, lighting removal, seams, and photo-pattern preservation as well as rendered appearance. Compare against the existing deterministic estimator and unrefined DA3 on identical crops. Promote a model only when it improves the exported Cycles material and records its checkpoint, license, input size, and refinement strength in the recipe.

No training data were downloaded, no refinement model weights were installed, and no LoRA was trained as part of this research review.
